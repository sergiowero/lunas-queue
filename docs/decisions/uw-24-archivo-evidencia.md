# UW-24 — Evidence file: written when each Run closes, left uncommitted and committed by delivery

- Status: accepted
- Date: 2026-10-29
- Unit: UW-24 · Code: `packages/server/src/evidence/`, `packages/schemas/src/evidence.ts`, `evidence` in `PhaseDispatcher` and `Orchestrator`, `commitPaths` and the exclusion of `lunasq/tasks/` in `packages/adapters/src/git/`, `uncommitted` in `packages/server/src/mcp/ports.ts`

## Context

`docs/design.md` (§Evidence file) asks for `lunasq/tasks/{id}.md` in the task's worktree, with one section per Run added when closing it, so that it travels in the branch and in the PR and survives the closing of herdr's pane and Claude Code's transcript retention. ADR uw-10-hooks, uw-11-gate-tests and uw-19-revisores left the material in the Event log and in `run_subagents`.

The file is inside the repo, and three pieces already done look at the worktree's git state:

- `submit_for_verification` and `submit_verdict` with a pass reject with `dirty_worktree` if there are uncommitted changes (UW-15, UW-23).
- The pass compares the `HEAD` with the commit that passed `submit_for_verification`'s gate: an evidence commit in between gives `head_changed` (UW-23).
- `HookService` does not commit what the hooks leave if the worktree was already dirty (UW-10).

## Decision

- **One section per Run, rewritten in place.** `EvidenceService.recordRun(runId)` builds the closed Run's section and inserts or replaces it between the markers `<!-- lunasq:run:start <id> -->` and `<!-- lunasq:run:end <id> -->`. Repeating it with the same data does not change the file, so retries and reconciliation are safe. The sections stay in order of first closing; the header (task and intent) is regenerated and whatever is not a section is discarded. An open Run, a nonexistent one or one of a task without a worktree is skipped without error. The writes of the same task go in order (`KeyedLock`) and the file is written to a temporary and renamed.
- **Section content** (`renderRunSection`, pure function): phase, agent, model, iteration, start, end, result, `failure_reason` and session; the handoff as a JSON block; in verification, the full verdict (per criterion, each reviewer's report or justification, must-fix and refuted findings with their reason; if the handoff does not validate against the current schema it falls back to the JSON); the output of each execution of the gate (`test_gate.executed`) and of each hook (`hook.executed`, `hook.point_completed`) of the Run, read from the Event log; and the transcripts. Only events whose `runId` is the Run's enter.
- **Transcripts.** `ClaudeTranscriptSource` reads `~/.claude/projects/<cwd with non‑alphanumerics → "-">/<session>.jsonl` (also by the worktree's real path) and, for each subagent, the `transcript_path` stored by the `SubagentStop` hook (ADR uw-19-revisores). `transcriptToMarkdown` keeps user and agent turns, tool calls and their results; it omits internal reasoning and metadata messages, trims the tool results (start and end), the text blocks and the whole transcript, and goes inside a `<details>` per transcript. A transcript that is missing or weighs more than 32 MiB leaves a note in its place. **The `transcript_path` is sent by a hook that anyone with the run token can call, so it is only read if it is a `.jsonl` whose real path lies in this worktree's project directory inside `~/.claude/projects/`** (without following symlinks outside): otherwise an arbitrary file or another task's transcript could be dumped into the PR.
- **Secret redaction** (`redactSecrets`) over the whole section, not just the transcripts: the gate's output, the hooks and the handoff can also carry secrets. Gitleaks‑style patterns: private keys (also truncated), GitHub, AWS, Anthropic, OpenAI, Slack, Stripe, Google and npm tokens, JWT, `Bearer`, credentials in URLs, the run token (header and environment variable) and assignments to names such as `secret`, `token`, `password`, `api_key` (the name is kept and the value is redacted). The Run's own run token is also redacted literally. It is idempotent. The transcripts are redacted **before** trimming them (a trim can leave out a key's BEGIN and the rest would no longer match any pattern), and there is also a rule for a key's orphan body (base64 lines + END). Quoted values are redacted whole, also with escaped quotes (JSON inside JSON), and `Basic` and `-p<password>` are covered. The rules have bounded quantifiers so as not to degrade on long texts. It prefers over‑redacting: the file ends up in git history. It is not infallible; a secret without a recognizable shape gets through.
- **Markers proof against the agent's content.** Any `<!-- lunasq:` that comes in a transcript, a handoff or the intent is rewritten as `<!-- lunasq-escapado:`, so an agent cannot close its section early or plant another Run's.
- **Who calls it.** `PhaseDispatcher` receives `evidence?: RunEvidenceSink` and calls `recordRun` in `closeRun`, `failRun` and `releaseRun`, after closing the Run **and closing the pane**, so the agent is already stopped and its transcript complete (an MCP exit tool closes the Run while the agent finishes its turn); if closing the pane fails, the evidence is written anyway. Those three cover the closings: those of the dispatcher and reconciliation (`closeRun`, `failRun`, including failures on launch) and those of the MCP exit tools, which close the Run in their transaction and which the `Orchestrator` reaches with `releaseRun` when the task leaves `running` (ADR uw-16-dispatcher). `Orchestrator` passes `evidence` to the dispatcher. A failure while writing is reported through `onError` and does not prevent closing the Run or the pane. The verdict with a pass leaves its Run open until delivery (ADR 0007): its section is written when UW-26 closes it.
- **The file stays uncommitted during the loop.** `GitAdapter.isDirty` and `commitAll`, and `GitCommitVerifier.uncommitted`, ignore `lunasq/tasks/` with an `:(exclude)` pathspec. This way the file neither triggers `dirty_worktree` nor makes `HookService` skip committing its changes. The pass tolerates that the `HEAD` has advanced since `submit_for_verification`'s gate when all the intermediate commits touch only `lunasq/tasks/` (`GitCommitVerifier.onlyEvidenceBetween`); the pass's gate runs anyway on the current `HEAD`, so the verdict still judges the code being tested. Before the rebase, delivery commits the pending evidence so that what is tracked does not dirty the worktree, and commits it again after closing the verifier's Run. Committing at every close was discarded (it added noise and required relaxing the gate further) and so was writing it outside the worktree (contradicts the design and forces copying it at delivery).
- **Safe writing.** The worktree belongs to the agent: before writing, `lstat` checks that `lunasq/` and `lunasq/tasks/` are not symlinks (if they are, `recordRun` rejects and the dispatcher reports it), and the temporary has a random name and is opened with `wx`; if it fails, it is deleted.
- **Commit.** `GitAdapter.commitPaths({ cwd, paths, message, trailers })` adds with `--force` (the project may ignore `lunasq/tasks/` in its `.gitignore`) and commits only those paths with `--only`, without touching the rest of the index or the working tree; it returns null if there are no changes. `EvidenceService.commit(taskId)` uses it for the task's file with the `LunasQ-Task` and `LunasQ-Run` trailers (last Run). FakeGit and RealGit satisfy the same contract suite.
- **Shared constants** in `packages/schemas/src/evidence.ts`: `EVIDENCE_DIR`, `evidencePath` and the trailers `COMMIT_TRAILER_TASK` and `COMMIT_TRAILER_RUN`, which `HookService` already used as local constants.

## Consequences

- **Limitation: Run closed by the MCP with another Run already open.** `Orchestrator` calls `releaseRun` only for the task's last Run on receiving `task.transitioned`. If the outbox message is delivered late (restart, delay) when the task already has a new Run, the earlier Run closed by the MCP does not go through `recordRun`. `recordRun` is idempotent, so UW-29 can close the gap with a reconciliation sweep.
- **Limitation: previous sections are kept from disk as they are.** The worktree belongs to the agent, which could edit or delete an earlier Run's section before delivery. It is accepted in v1: the file is reviewed by the human in the PR and the Event log and the `runs` table are the source of truth. Regenerating all the sections from the database on every close is the improvement if needed.

- **UW-26** must call `EvidenceService.commit(taskId)` before delivery's push, after closing the verifier's Run (so its section is there) and after the final gate, and call it again if delivery closes more Runs. The commit enters the branch and the PR.
- **UW-29** composes `EvidenceService` (with `RealGit` and `ClaudeTranscriptSource`) and passes it as `evidence` to `Orchestrator`.
- An agent that runs `git add -A` in its worktree can commit the half‑written file inside its own commit; the branch's history may show it in an agent commit. `commitPaths` commits the final version and, if that commit happens after `submit_for_verification`'s gate, the pass accepts it only if it touches no code. A file that is already tracked and changes after the commit stays as an uncommitted change and blocks any `git rebase` by the agent or by delivery: that is why delivery commits the pending evidence before the rebase.
- If the worktree is deleted before a Run closes (cancellation with cleanup), there is nowhere to write and the section is lost; the Event log and the `runs` table keep the data.
- The line format of Claude Code's transcripts is not a stable contract. The converter reads only `type`, `message.content` and `timestamp`, and skips what it does not recognize; an unreadable line is counted in a note.
