# UW-14 — GitHub adapter (gh) and merge detection by polling

- Status: accepted
- Date: 2026-10-29
- Unit: UW-14 · Code: `packages/adapters/src/github/`, `packages/schemas/src/pull-request.ts`, `packages/domain/src/pull-requests.ts`, `packages/db/src/task-prs.ts`, `packages/server/src/github/`

## Context

`docs/design.md` (§External integrations and §Decisions) asks to talk to GitHub only through the `gh` CLI, behind an adapter: create the PR, read CI and reviews and detect merges by polling in v1. A task is *ready* when all its dependencies have their PR merged, and if a dependency's PR is closed without merge, its dependents move to Needs human. UW-13 (ADR 0014) already computes the ready set with `prState = merged` and escalates the dependents of a closed PR; what was missing was who would record the PR's state. UW-14's criterion: a detected merge releases the dependent tasks.

## Decision

- **`GitHubAdapter` port** (`@lunasq/adapters`): `createPr`, `findOpenPr` and `getPr(url)`. `PullRequest` carries number, URL, state (`PrState` from `@lunasq/schemas`), draft, branches, `mergedAt`/`closedAt`, checks (each `pending | success | failure | skipped` and a summary `none | pending | success | failure`: a failure wins, then a pending) and reviews with their `reviewDecision` (null if the repo does not require reviews).
- **Idempotent `createPr`.** It first looks for an open PR from `head` to `base` (`gh pr list --state=open`) and, if it exists, returns it with `created: false`. If `gh pr create` fails with "already exists" (another process opened it in between), it searches again and returns that one. A closed or merged PR does not count: another is opened. Publishing the branch belongs to delivery (UW-26), not to the adapter.
- **No shell.** `RealGitHub` runs `gh` with `execFile` and separate arguments in the form `--flag=value`: title and body come from agents and must not be able to inject commands or pass as another option if they start with `-`. The body goes in through stdin (`--body-file=-`). `GH_PROMPT_DISABLED=1` avoids prompts; each command has a timeout (60 s by default). `getPr` uses the URL and needs no checkout.
- **Errors.** `GitHubError` with `code`: `gh_unavailable` (binary missing), `not_authenticated` (exit 4 without a session, or a 401 / `Bad credentials` with an expired or revoked token), `not_found` (gh 2.100 messages for a nonexistent PR or repo, or a reference that is not a PR's URL), `timeout`, `invalid_output` and `gh_failed` (includes a cwd that no longer exists, an output larger than the buffer and a process killed by an external signal).
- **Tolerant parsing.** The `--json` output is validated with Zod without strict schemas, because gh adds fields between versions. Checks and reviews are read one by one: a check of unknown shape counts as `pending` and an unknown review is discarded, so a new kind of check never prevents reading the PR's state (otherwise the poller would not see the merge). `createPr` requires the output of `gh pr create` to end with the PR's URL, and `getPr` only accepts URLs: with a number or an empty argument, `gh` would resolve against the repo of the server's directory.
- **Fake and contract.** In‑memory `FakeGitHub` with controls (`merge`, `close`, `reopen`, `setChecks`, `addReview`, `failGetPr`). The contract suite runs against the fake in `pnpm test` and against real GitHub with `LUNASQ_GH_SANDBOX_REPO=<owner>/<repo> pnpm --filter @lunasq/adapters test:gh`: it clones the sandbox, publishes `lunasq-contract/*` branches, opens, merges and closes PRs and deletes the branches at the end. It does not run in CI.
- **The PR only moves forward.** `prStateChange` (domain) allows only `open → merged | closed`; stale data never reverts a merge. A new PR (another delivery after a close without merge) or the same PR reopened on GitHub are recorded with `recordPrOpened`, which rejects opening another if the current one has already been merged (`pr_already_merged`) or is still open (`pr_already_open`): replacing it would take it out of the poller and its merge would not be seen.
- **Recording in the database.** `TaskPrRepository` (implements the `PrTrackingStore` port) only touches `pr_url` and `pr_state`, in `IMMEDIATE` transactions, and leaves its event published in the outbox with actor `system`: `task.pr_opened` (`url`, `previousUrl`) and `task.pr_state_changed` (`url`, `from: open`, `to`, `at` = time of the merge or the close according to GitHub). What is observed about a PR that is not the task's current one is ignored. Repeating a record writes nothing.
- **Poller.** `PrPoller` (server) queries on each pass the tasks with an open PR, one by one, and records the changes. Interval of 60 s by default (minimum 1 s). Passes do not overlap, as in the scheduler: a request during a pass asks for one more. A PR that fails (network, rate limit, deleted PR) is reported with `onError` and the pass continues. If it recorded something, it wakes the outbox publisher.
- **Releasing and escalating belongs to the scheduler.** The outbox event triggers a scheduler pass (subscribed to `*`, ADR 0014), which dispatches the already ready dependents and escalates with `dependency_pr_closed` those of a closed PR. UW-14 does not duplicate that rule. A test composes poller, outbox and scheduler and checks both cases.

## Consequences

- **UW-26** (delivery) calls `createPr` after the push and records the result with `recordPrOpened` before `verdict_pass` (`prCreated`). It also composes the process: creates the `PrPoller` with the publisher and calls `start()` and `stop()`.
- **UW-10** (`after_merge`) and the removal of the worktree after the merge (UW-17, UW-26) react to `task.pr_state_changed` with `to: merged`.
- **readySince.** The scheduler keeps using the dependency's `updatedAt`, which is now the time LunasQ detected the merge: the moment the dependent could start. GitHub's time stays in the event in case it is needed.
- **Cost.** One `gh` call per open PR on each pass. With v1's volume it is enough; if it grows, it is grouped with `gh api graphql` or moved to the webhook (v2, §Roadmap).
- **A deleted or moved PR** (`not_found`) stays in the open list and fails on every pass, reported with `onError`. If it bothers, a cap that escalates to needs\_human is added.
- **Several remotes.** `gh pr create` in a checkout with several remotes and no default repo may fail instead of asking (`GH_PROMPT_DISABLED`); delivery (UW-26) must run in the project's worktree, with `origin` as the remote.
- **A PR reopened on GitHub** without LunasQ recording it is not queried again: the poller only looks at open ones. Delivery records it when re‑delivering (`findOpenPr` finds it).
