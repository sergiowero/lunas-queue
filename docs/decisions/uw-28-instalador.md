# UW-28 — Installer: `lunasq install`, `doctor` and `start`

- Status: accepted
- Date: 2026-10-29
- Unit: UW-28 · Code: `packages/cli/src/` (`install.ts`, `doctor.ts`, `assets.ts`, `config.ts`, `paths.ts`, `main.ts`, `bin.ts`), `packages/cli/scripts/build.ts`, `packages/server/src/runtime/`

## Context

`docs/tech-stack.md` defines a `lunasq` binary published on npm with three commands. `install` verifies herdr, Claude Code and `gh`, installs the herdr integration for Claude Code, copies skills and subagents, registers the LunasQ MCP and configures telemetry. UW-28's criterion: a clean machine is ready with a single command and `lunasq doctor` in green. The earlier units left pending items for this one: the MCP file's path and the server's URL (ADR uw-16-dispatcher), the hooks settings (ADR uw-19-revisores), the skills' destination (ADR uw-18-skills-fase) and the notice for toasts turned off (ADR 0009). `app.ts` also did not yet mount the HTTP server.

## Decision

- **Everything in `~/.lunasq/`.** There go `config.json` (`port`, 7360 by default, and `telemetry`, `true` by default), `lunasq.db`, `mcp.json` (ADR 0002) and `claude-settings.json` (ADR uw-19-revisores). `LUNASQ_HOME` changes the directory. Skills and subagents go to `CLAUDE_CONFIG_DIR` or, if not defined, to `~/.claude`, the same variable that Claude Code respects. The MCP and hooks URLs come from the port with `runtimeUrls`, and `install` and `start` use the same function.
- **The MCP is not registered at user level.** Registering the MCP means writing the stable file that the dispatcher passes with `--mcp-config --strict-mcp-config`. With `--strict-mcp-config`, a user registration (`claude mcp add -s user`) does not reach the agent. Besides, every Claude Code session of the user would try to connect without a run token and the server would reject it. `docs/tech-stack.md` said "Registers the LunasQ MCP at user level" and is corrected.
- **Requirements that are not installed.** If herdr, Claude Code or a `gh` session is missing, `install` stops before writing anything and lists what is missing. It does the same with an invalid `config.json`, and names the file. The minimum versions are those of the spikes: herdr 0.9.5 (ADR 0004), Claude Code 2.1.312 (ADR 0002, ADR uw-19-revisores) and Node.js 26. A herdr that does not speak protocol 22 produces a warning and not a failure, because it is newer and unverified, not incompatible.
- **herdr integration.** The status comes from the `claude:` line of `herdr integration status`. `install` runs `herdr integration install claude` only if that status is not `current`. herdr installs into `CLAUDE_CONFIG_DIR` and fails if the directory does not exist, so `install` creates it first.
- **Assets as a mirror, only over its own.** Each skill folder (`assets/skills/<name>/`) and `assets/agents/lunasq/` are copied as an exact mirror: a file that is no longer in the assets is deleted from the destination. `doctor` marks as outdated an asset edited by hand, and `install` restores it. The per‑project override (`.claude/skills`, `.claude/agents`) remains the way to customize.
  - `~/.lunasq/installed-assets.json` records the destinations that LunasQ installed.
  - The skills have generic names (`implement-task`), so a folder that already exists, is not in the manifest and is not identical to the assets belongs to the user. `install` does not touch it, and `doctor` fails with the instruction to move it. An identical one is adopted.
  - A manifest destination that no longer corresponds to any asset (a retired or renamed skill) is deleted on the next `install`. While it is still there, `doctor` fails.
- **Telemetry.** `startRuntime` passes in the dispatcher's `paneEnv` the OTLP variables from `docs/tech-stack.md` towards `http://127.0.0.1:<port>`. The per‑Run attributes and the `/v1/metrics` and `/v1/logs` endpoints were added by UW-20 ([ADR uw-20-usage-collector](uw-20-usage-collector.md)). `telemetry: false` in the configuration turns them off.
- **`doctor`.** Each check ends in `ok`, `warn` or `fail`, with the action that resolves it. Green means no failures, and in that case it exits with 0. It checks Node.js, that better-sqlite3 loads and applies the migrations in memory (ADR 0003), herdr and its server, the integration, Claude Code, `gh auth status`, each skill, the reviewers, the configuration, that `mcp.json` and the settings correspond to the port, and telemetry. It only warns if herdr's toasts are off (`[ui.toast] delivery` in `HERDR_CONFIG_PATH` or `~/.config/herdr/config.toml`, ADR 0009) or if engram is not installed (weak dependency). herdr's key is read with a minimal TOML reader, without adding a parser. `--json` prints the results for scripts.
- **`start` is composed by `server`.** The boundaries matrix lets `cli` depend only on `server`, so `startRuntime` (in `packages/server/src/runtime/`) builds the process. It opens the database and applies the migrations, listens on `127.0.0.1` before composing (with port 0 the real URL goes into Claude Code's files) and mounts `createApp` with `PaneTestGate`, `HookService` and the notifications SSE at `/api/notifications`. Then it starts `OutboxPublisher`, `Orchestrator`, `PrPoller` and the `after_merge` hooks. `stop()` is idempotent and also closes open SSE connections. If the composition fails, it closes the server and the database before propagating the error. `lunasq start` reads the configuration, prints the URL and stops with SIGINT or SIGTERM. On the first signal it removes both listeners, so a second signal ends the process even if `stop()` hangs. The server imports `@hono/node-server`, which was already in the stack. `server` re‑exports `adapters`' `ProcessRunner` for the CLI's checks.
- **npm package.** Node.js does not strip types inside `node_modules`, so the package cannot publish the monorepo's `.ts` files. `pnpm --filter @lunasq/cli build` builds `packages/cli/dist/` with esbuild (a new development dependency, already in the lockfile through drizzle-kit). The result has a single ESM bundle at `bin/lunasq.js`, with everything except better-sqlite3, which is native and ships a prebuild. Next to it go `drizzle/` and `assets/`, which the bundle looks for in `bin/..`, and a `lunasq` `package.json` with `bin` and better-sqlite3 as the only dependency. In the repo, `pnpm lunasq <command>` runs `src/bin.ts` directly. The `@lunasq/cli` workspace stays `private`, and what is published is `dist/` (`npm publish packages/cli/dist`).

## Verification

- Unit tests with a temporary home and a `FakeProcessRunner` that answers like herdr, Claude Code, `gh` and engram. They cover: a clean machine is green after `install`, repeating it changes nothing, each missing requirement stops the installation without writing, and each check fails or warns in its case.
- `startRuntime` with fakes: serves the API, writes the files with their URL, mounts the SSE, passes the telemetry, `stop` is idempotent and a busy port fails.
- The bundle is built in the test, runs `--version` and `doctor --json`, applies the migrations and finds the assets.
- By hand, on this machine with Node.js 26.13, herdr 0.9.5, Claude Code 2.1.314 and real `gh`, on a temporary `LUNASQ_HOME` and `CLAUDE_CONFIG_DIR`: `lunasq install` exited with 0, a second `install` changed nothing, `doctor` stayed green with a single warning (toasts off) and `start` served `/api/projects` and stopped with SIGINT.

## Consequences

- **UW-02 (finding):** with `start` against the user's real herdr, `session.snapshot` brings agents without a `name` (Claude Code sessions that the user opened by hand and that the integration detects), and the adapter's schema rejects them. Every reconciliation pass fails with `invalid_type` at `snapshot.agents[i].name`. It is left as a separate task for the adapter. The pilot (UW-29) needs it resolved.
- **UW-20:** mounts `/v1/metrics` and `/v1/logs` in `createApp` and adds the per‑Run `OTEL_RESOURCE_ATTRIBUTES` in the dispatcher. The base telemetry already reaches each pane.
- **UW-21:** serves the front end's static files from `startRuntime`.
- **UW-29:** the pilot uses `lunasq install` and `lunasq start`. Publishing to npm (`npm publish packages/cli/dist`, with the version bumped in `packages/cli/package.json`) is left as a manual step for whoever releases, because it needs credentials and is an external action.
- `doctor` does not repeat the real reviewer test with Claude Code (ADR uw-19-revisores), because it spends tokens. It stays in `pnpm --filter @lunasq/server test:claude`.
- It does not pre‑accept folder trust in `~/.claude.json` either: the dispatcher already resolves the dialog (ADR uw-16-dispatcher).
