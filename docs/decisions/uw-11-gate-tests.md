# UW-11 — Test gate in a herdr pane, with its result in the Event log

- Status: accepted
- Date: 2026-10-29
- Unit: UW-11 · Code: `packages/server/src/test-gate/`, `packages/schemas/src/test-gate.ts`, `envAllowlist` in `packages/adapters/src/process/`, `submitVerdict` in `packages/server/src/mcp/service.ts`

## Context

`docs/design.md` (§Engineering practices) asks LunasQ to run the project's test command in the worktree on receiving `submit_for_verification` and again before accepting a pass, without trusting what the agent reports. `docs/tech-stack.md` asks it to run in a herdr pane with a wrapper that records the exit code and output. UW-15 left the `TestGate` port with `ShellTestGate`, which ran the command in LunasQ's process, inherited its environment (with `gh`'s tokens), stored nothing and did not run before the pass. UW-11's criterion: a red suite blocks the transition even if the agent says otherwise.

## Decision

- **`PaneTestGate`** (server) implements the `TestGate` port. It opens a pane from the worktree's root (`WorktreeService.ensure(taskId).rootPaneId`; with the worktree already ready, `ensure` only returns it, and if its path is not the Run's the gate fails closed) with `HerdrPaneRunner` (ADR uw-10-hooks), runs the command in the worktree with a 20‑minute timeout (`DEFAULT_GATE_TIMEOUT_MS`) and closes the pane. It passes only with exit 0 and no timeout. Without a test command (or with an empty one), without a worktree or with herdr down it fails closed: there is no pass without a green suite.
- **Minimal environment.** `ProcessInput.envAllowlist` (adapters): if present, the command runs with `env -i` and only the variables from the list that are defined, plus those in `env`. `ShellProcessRunner`, `HerdrPaneRunner` (the wrapper builds the list in the pane's shell) and the fake implement it. The gate uses `GATE_ENV_ALLOWLIST` (`PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `TMPDIR`) and adds `CI=1`, `LUNASQ_TASK_ID` and `LUNASQ_RUN_ID`. `GH_TOKEN`, API keys and the rest of the herdr server's environment do not reach the suite. `CI=1` avoids watch and interactive modes.
- **Recording.** Each execution leaves `test_gate.executed` (actor `system`, published in the outbox) with Run, trigger (`submit_for_verification`, `verdict_pass` or `delivery`), command, sha of the `HEAD` tested (40 or 64 characters, for SHA-256 repos), exit code, timeout, duration, result, the last 16 KiB of the output and the error if it did not run. The schema requires `passed` to match exit 0, no timeout and no error. It is also recorded when it fails closed. No new table, like `hook.executed`: the evidence file (UW-24) reads these events.
- **To the agent** the tail of the output (4000 characters, `GATE_OUTPUT_LIMIT`) arrives with `test_gate_failed`, plus a line with the reason if there was a timeout or error.
- **Gate before the pass.** `submit_verdict` becomes async. With a pass and no verdict recorded in the Run: clean worktree (`dirty_worktree`; the verifier's reversal test touches the code) → `HEAD` equal to the `headSha` of the last green `test_gate.executed` with trigger `submit_for_verification` (`head_changed`), unless the intermediate commits touch only `lunasq/tasks/` and descend from that gate → gate with `verdict_pass` → clean worktree and same `HEAD` again, because the suite can take minutes → transaction. This way the verifier cannot approve a commit of its own that deletes or skips the red tests: verification judges exactly the code that passed the gate. Without that earlier green gate, the pass is rejected. A red pass answers `test_gate_failed`, does not store the handoff and leaves the Run open: the verifier can correct to reject. Repeating an already recorded pass does not run the suite again. A reject does not run the gate. The per‑Run `gate_in_progress` lock applies to both tools.
- **`ShellTestGate` is retired.** `createApp` receives the gate from whoever composes the server; without it, it uses `UnavailableTestGate`, which never passes.

## Consequences

- A commit in the worktree after the `submit_for_verification` gate invalidates the pass, also one made by the `after_implementation` or `before_verification` hooks; the exception is a commit that only touches the evidence, which the pass accepts because the pass's gate runs on the current `HEAD`. If UW-23 lets those hooks commit code, it must run the gate again with `submit_for_verification` on the new `HEAD` before dispatching the verifier; otherwise the pass answers `head_changed`.
- **Limits of the minimal environment.** The allowlist removes credentials from the environment, not from disk: with `HOME` the suite can read `~/.config/gh`, `~/.npmrc` or `~/.ssh`. An isolated `HOME` per execution would break caches and toolchains (pnpm, nvm). Closing it requires a sandbox, outside v1, as ADR uw-10-hooks says about the agent and the common gitdir.
- **The gate trusts the repo's content.** The agent controls the code the suite runs: it can change the repo's test command or, from the suite, write the exit code into the wrapper's directory. It is no worse than editing the test script. The real control is that the pass's `HEAD` is the one that passed the gate and the verifier's test coherence review.

- A suite that needs other variables (`DATABASE_URL`, `NODE_OPTIONS`) fails at the gate. The project sets them in its test command or in a script of the repo. If it repeats, a per‑project allowlist in the config (ADR 0008) is left for later.
- `submit_verdict` with a pass can also take up to the gate's timeout. The `MCP_TOOL_TIMEOUT` that UW-16 sets in the pane applies in all phases, so it covers it.
- UW-18 must indicate in the verification skill that the worktree be left clean (revert the reversal test) before the pass, and that `test_gate_failed` on a pass calls for a reject or fixing the environment.
- UW-26 runs the final gate after the rebase with the same `PaneTestGate` and the `delivery` trigger.
- The server composition (UW-29) builds `PaneTestGate` with `RealGit`, `RealHerdr` and the orchestrator's `WorktreeService` and passes it to `createApp`.
